# Project : Web Application Reconnaissance with Nikto

## Objective
Perform a web server reconnaissance scan against a local DVWA instance using Nikto to identify misconfigurations, outdated software, and missing security headers.

## Lab Setup
- **Platform**: Kali Linux
- **Target**: DVWA (Localhost, `http://127.0.0.1:42001`)
- **Tool**: Nikto v2.6.1

## Methodology
1. Started the DVWA web application locally on Kali Linux.
2. Executed a Nikto scan against the target URL (`nikto -h http://127.0.0.1:42001`).
3. Reviewed the findings for security misconfigurations and missing headers.

## Findings

The Nikto scan revealed several security misconfigurations in the web server:
- **Outdated Software**: The server is running `nginx/1.30.4`, which appears to be outdated (current is at least 1.31.3).
- **Missing Security Headers**: The server is missing several critical security headers, including:
  - `Content-Security-Policy`
  - `Strict-Transport-Security`
  - `X-Content-Type-Options`
  - `Referrer-Policy`
  - `Permissions-Policy`
- **Admin Interface Exposed**: An admin login page was discovered at `/login.php`.

### Key Takeaway
While Nikto is a scanner and not an exploit tool, the findings highlight poor server hardening. A SOC analyst might see the traffic generated by this scan as a high volume of `GET` requests and `404 Not Found` errors in the web server logs, indicating an automated reconnaissance attempt.

## SOC Relevance
Web application reconnaissance is a common precursor to exploitation. This project demonstrates:
- Understanding of web server hardening and common misconfigurations.
- Ability to use Nikto for vulnerability assessment.
- Recognition of scanning traffic patterns for detection.
