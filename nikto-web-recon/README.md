# Project : Web Application Reconnaissance with Nikto

## Objective
Perform a web server reconnaissance scan against a local DVWA instance using Nikto to identify misconfigurations, outdated software, and missing security headers.

## Lab Setup
- **Platform**: Kali Linux
- **Target**: DVWA (Localhost, `http://127.0.0.1:42001`)
- **Tool**: Nikto

## Methodology
1. Started the DVWA web application locally on Kali Linux.
2. Executed a Nikto scan against the target URL.
3. Reviewed the findings for security misconfigurations and missing headers.

## Findings

The Nikto scan revealed several security misconfigurations in the web server:
- **Missing Security Headers**: The server is missing headers like `X-Frame-Options` or `X-Content-Type-Options`, which can leave the application vulnerable to clickjacking or MIME-sniffing attacks.
- **Information Disclosure**: The server banner reveals version information (e.g., Apache/PHP versions), which attackers can use to look up known exploits.

### Key Takeaway
While Nikto is a scanner and not an exploit tool, the findings highlight poor server hardening. A SOC analyst might see the traffic generated by this scan as a high volume of `404 Not Found` errors and unusual `GET` requests in the web server logs, indicating an automated reconnaissance attempt.

## SOC Relevance
Web application reconnaissance is a common precursor to exploitation. This project demonstrates:
- Understanding of web server hardening and common misconfigurations.
- Ability to use Nikto for vulnerability assessment.
- Recognition of scanning traffic patterns for detection.
